# Enact

[Enact](../skills/build-enact-product/SKILL.md) runs Prism's agents in isolated sandboxes behind
one HTTP API and one MCP endpoint. This page covers two things:

1. [Connecting your editor to Enact](#connect-your-editor-to-enact-opt-in): off by default; you
   add it yourself.
2. [Packaging this kit's agents for Enact](#packaging-kit-agents-for-enact): how `enact/` is
   generated and checked.

## Connect your editor to Enact (opt-in)

The kit's `mcp.json` does **not** include an `enact` server, and it will not: the endpoint needs
an environment key, and most people never start Enact runs from their editor. Add it yourself
when you want to start Enact runs (`list_agents`, `start_run`, `get_run`, `send_message`) from
Claude Code or Cursor.

You need the environment's shared domain and its API key. Keep the key in your shell
environment as `PRISM_API_KEY` (for example in `~/.zshrc`); never paste it into a file in a
repository or into chat.

**Claude Code**: add the server to your user configuration so it is not committed anywhere:

```bash
claude mcp add --scope user --transport http enact "https://<shared domain>/enact/mcp" \
  --header 'x-api-key: ${PRISM_API_KEY}'
```

The single quotes keep `${PRISM_API_KEY}` unexpanded, so Claude Code reads the key from your
environment when it connects instead of storing it. Run `claude mcp list` and confirm `enact`
shows `Connected`. If it fails to authenticate, your Claude Code version does not expand
variables in user configuration: remove it and add it again with double quotes
(`--header "x-api-key: $PRISM_API_KEY"`), which stores the key in your private
`~/.claude.json`.

**Cursor**: add this entry to `~/.cursor/mcp.json` (your user file, not the kit's `mcp.json`):

```json
{
  "mcpServers": {
    "enact": {
      "url": "https://<shared domain>/enact/mcp",
      "headers": { "x-api-key": "${env:PRISM_API_KEY}" }
    }
  }
}
```

Restart Cursor from a terminal where `PRISM_API_KEY` is set, then check **Settings → Tools &
MCP**.

To turn it off again, run `claude mcp remove --scope user enact` or delete the entry. Enact's
own `docs/mcp.md` describes the endpoint and wins over this page.

## Packaging kit agents for Enact

`agents/` stays the source of truth. `scripts/sync-enact-agents.mjs` (Node, standard library
only) turns each agent into an Enact agent directory, following Enact's
`docs/agent-contract.md`:

```text
enact/
├── config.json             # input: stays-local set, waves, model map, defaults, MCP lists
├── overrides/<agent>.json  # input: manifest fields, requires_mcp (+ reason), needs_secrets, browser, appendix lines
├── schema/                 # input: Enact's agent and skill schemas + SOURCE_REVISION (scripts/sync-enact-schema.sh)
├── inventory.json          # generated: wave, size, skills, flags, requires_mcp, blocked_by per agent
├── dist/                   # gitignored: packed PUT bodies for Build's enact agent/skill kinds
│   ├── agents/<agent>.json # {manifest, files, assets?} as canonical JSON
│   ├── assets/<sha256>     # each asset's bytes, uploaded before the agent's save
│   └── skills/<skill>.json # library skills
├── library/                # generated: the skill library
│   ├── index.json          # committed: library skills: version, digest, sizes, users; skills it cannot hold
│   └── <skill>/            # gitignored: skill.json + the skill's files
└── <agent>/                # generated, one per agent not in stays_local
    ├── agent.json          # manifest: frontmatter + config defaults + override
    ├── instructions.md     # agent body + "Running on Enact" appendix
    └── skills/             # gitignored: regenerated by `sync`
```

```bash
node scripts/sync-enact-agents.mjs sync     # after changing agents/, skills/ or enact/ inputs
node scripts/sync-enact-agents.mjs check    # CI: committed agent.json/instructions.md/inventory are current
python3 scripts/test-enact-packaging.py     # T1 (after sync); --strict for every agent, --self-test
scripts/sync-enact-schema.sh [sync|check]   # refresh enact/schema from prismteam-ai/enact origin/main
```

### The skill library

A skill goes to the library, instead of being copied into each package, when two or more packaged
agents use it, or when keeping it among an agent's own files would break that agent's limits
(1 MiB, 200 files, 256 KiB per file; the skill holding an over-limit file goes first, then the
largest). The generator writes `enact/library/<skill>/` (`skill.json` and the skill's files, with
`disable-model-invocation` removed as in packages; gitignored) and `enact/library/index.json`.

**Library skill versions are content-derived**: `1.0.0-sha256-<16 hex>`, the first 16 hex digits
of the SHA-256 of `{name, description, files}` as stable JSON. A version always names the same
content, so a save never meets `409 VERSION_CONFLICT`, unchanged skills keep their version across
kit releases (nothing is re-saved), and any change is a new version. Agents pin exact versions, so
the versions need no order. `index.json` also records each skill's `digest` (`sha256:` over the
stored document's canonical JSON, as Enact computes it), bytes, files, stored bytes, why it is in
the library and which agents pin it.

Skills the library cannot hold (over 3 MiB of text, over 5 MiB encoded or a 4 MiB body, over 500 files, binary files, paths it
refuses such as dotfiles, or no description) stay in their agents' packages and are listed under
`excluded` with their users. Today those are `prism-asset-pipeline` (images; used only by
ampharos) and `use-oracle` (`runtime/.dockerignore`, `.gitignore`; used only by oracle, which
stays local).

**Assets.** An agent's own skill may hold binary files (Enact's `assets`, enact#33): every file
that is not UTF-8 text, and in such a skill also every text file over the 256 KiB file limit,
goes into the package's `assets` by SHA-256 and size instead of `files` (at most 32 MiB each,
128 MiB and 500 together; `blocked_by: agent-assets` past that). `sync` writes their bytes to
`enact/dist/assets/<sha256>` and into the agent directory. Saving uploads each one first:
`POST /enact/agents/{name}/assets {sha256, bytes}`, then, unless it answers `stored: true`, a `PUT`
of the bytes to its `upload.url` with its `upload.headers`. Today only ampharos has assets: 32
reference images and indexes, 21.7 MB. `.gitkeep` files are not packaged.

### What the generator does

- **Manifest.** `name`, `description` and `model` come from the agent's frontmatter. The
  version is `1.<kit minor>.<kit patch>` (kit `0.158.0` → `1.158.0`): each kit release is a new
  Enact version, and every generated version sorts above the hand-made `slowking` 1.0.0 that was
  deployed in Enact before the generator existed. Moving the kit to `1.x` would need a new rule
  (such as `2.<minor>.<patch>`) so versions keep rising. Kit models map through
  `config.json` `model_map` (`gpt-5.5-high`/`gpt-5.4-high` → `opus`, `*-medium` → `sonnet`,
  `*-low`/`*-mini` → `haiku`; no model → `default_model`). `default_manifest` sets limits,
  channels, repositories and hosts; `overrides/<agent>.json` `manifest` replaces any field.
- **Instructions.** The agent body, then a "Running on Enact" appendix: the sandbox (Node.js and
  git; `curl`, `jq`, `unzip`, `python3`, `gh` and `aws` only on images with enact#22, so check
  with `command -v`, prefer Node.js `fetch` and fall back to `curl`; no AWS profile, and `gh`/`aws`
  are not signed in), nobody answering mid-run, the installed skills, the tools (including other
  agents through the `enact` server's `ask_<agent>` tools, enact#24, when a run has that server),
  the repositories, the network, read-only rules for `readonly: true` agents, and how to return
  the result. The wording holds before and after those pieces merge. `overrides/<agent>.json` `appendix` adds agent-specific lines.
- **Skills.** The transitive closure of skills the body references as `skills/<name>/`, plus the
  skills each included `SKILL.md` references (as `skills/<name>/` or `../<name>/`). Files come
  from `git ls-files`; non-UTF-8 files are omitted and listed in the inventory.
  `disable-model-invocation` is removed from each copied `SKILL.md` (Enact has no slash commands);
  the editor packages keep it.
- **Inventory.** Per agent: wave (`config.json` `waves`, then `requires_mcp` outside the
  allow-list → 4, `role: configure` → 2, `role: build` → 3, otherwise 3), bytes, files, skills,
  `requires_mcp` with its reason, `needs_secrets`, flagged assumptions (`curl`, `python3`, `gh`,
  AWS profile) as `file:line`, and `blocked_by`:

  | `blocked_by` | When |
  | --- | --- |
  | `shared-skill-library` | Own files still over 1 MiB, 200 files or 256 KiB in one file, or pins over 100 or 8 MiB |
  | `mcp-allow-list` | `requires_mcp` names a server outside `mcp_builtin` + `mcp_allow_list` (default `[]`) |

  Only an agent that opens an app it runs inside its sandbox needs `browser.sandbox_localhost`;
  the `browser` tool alone reaches hosted URLs, so slowking (candidates' hosted runtimes) does not.

### Packed files for Build

Build's `enact` configuration kinds (`agent`, and `skill` from prismteam-ai/build#66) take one
JSON file per agent or library skill: the exact `PUT /enact/agents/{name}` or
`PUT /enact/skills/{name}` body `{ manifest, files }`. `sync` writes them to
`enact/dist/agents/<agent>.json` and `enact/dist/skills/<skill>.json` (gitignored).
Each is the document's canonical JSON (keys sorted at every level, no whitespace), so the file's
SHA-256 is Enact's version digest (`sha256:…`) that Build records. T1 checks every packed file
parses back to its directory's manifest and files, is byte-for-byte canonical, and fits the PUT
body limit (2 MiB for agents, 4 MiB for skills).

### The configuration bundle

The bundle is not in this repository. [prismteam-ai/agent-network](https://github.com/prismteam-ai/agent-network)
holds it, and this repository writes it. On every push to `main`,
[`.github/workflows/publish-enact.yml`](../.github/workflows/publish-enact.yml) runs
`node scripts/sync-enact-agents.mjs sync` in a job with no secrets, then signs in as the
`agent-network-sync` GitHub App, runs agent-network's `scripts/generate.mjs` on the packed files
and pushes the result to its `main`. agent-network's pipeline installs that commit into the dev
environment and, when that succeeded, publishes it to Marketplace.

Only that App may change agent-network's generated files (a push ruleset there), and only this
workflow holds its key: the `agent-network` environment here, limited to `main`, has the variable
`AGENT_NETWORK_APP_ID` and the secret `AGENT_NETWORK_APP_KEY`. After agent-network's `kit.json`
or generator changes, run **Publish Enact agents** by hand (Actions, Run workflow) to regenerate.

The bundle holds only the agents the [README's Product agents table](../README.md#product-agents)
lists (each assigned product's builder and configurer) and the library skills they pin. Retained
specialists stay packaged under `enact/` here and are not installed. Which listed agents stay out
for now, and why, is that repository's `kit.json`. Nothing here is committed for the bundle; it
depends on that command, on the layout of `enact/dist/` and on the README's `product-catalog`
block, which `scripts/product_catalog.py sync` writes.

**What an agent or skill may not hold.** Deploy fills `{{parameter:name}}` and `{{secret:name}}`
in every file of a bundle, and an Enact document must be saved unchanged, so Build refuses an
agent or library skill whose text holds one, and any literal credential (a Secrets Manager ARN,
an AWS access key id, a private key). Write placeholder examples as `{{parameter:<name>}}` and
describe a credential instead of showing one. T1 fails on them and names the file.

### Declaring MCP needs

`requires_mcp` is declared in `overrides/<agent>.json`, never matched from text: many skills
mention Figma, Persist or Report MCP servers in prose without needing them. Declare a server only
when the agent calls `mcp__<server>__…` tools or its instructions require an MCP server to do
its work, and write why in `requires_mcp_reason` with the file and line.

### T1

`scripts/test-enact-packaging.py` validates each package against `enact/schema/`, the 1 MiB
limit, a `SKILL.md` in every skill, no path that is also a folder, and `requires_mcp` against the
allow-list. CI fails on agents in `must_pass_waves` (wave 1a) and reports the rest. `--self-test`
proves the checks catch each case, including that `donphan` fails on its `elephant` MCP server.

T1 also checks the library as Enact main does: each library skill against
`skill-definition.schema.json`, at most 3 MiB of text in 500 files, at most 5 MiB as its
canonical JSON encoded once more as a JSON string (how API Gateway carries it, so quotes,
backslashes and newlines count twice), a PUT body of at most 4 MiB, and a version that still
names its content; each agent's pins exist in `index.json` at that version, are at most
100 and 8 MiB (stored canonical JSON) together, and none is also an own `skills/<name>/`; `mcp_servers` are on the
allow-list. `--allow-list-from https://<shared domain>` adds the servers a live environment
allows (`GET /enact/mcp-servers` with `x-api-key: $ENACT_API_KEY`); without `ENACT_API_KEY` it
says so and uses `config.json` `mcp_allow_list`.
